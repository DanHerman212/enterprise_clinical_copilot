# §2 — Agent Harness

## Scope

This section covers `projects/agent-harness/agent/` — the live agent that turns a clinician's question into a grounded, cited answer by driving Gemini and the MCP tools. It is the core of the system: the service Django proxies to (§1), and the caller of the predict and RAG tools reviewed in §3. The deployed surface is a Starlette app on Cloud Run with a shallow health check and a single `/ask` route that validates the question, opens a fresh MCP session per request, runs the graph, and returns the answer with its guardrail flags, tool-call transcript, and A2UI canvas.

The graph is an explicit LangGraph, deliberately not `create_react_agent`: the agent turns once to emit tool calls, a tool node executes them, and the agent turns again to narrate — the second turn is where the prompt's behavioral contract applies. The model is Gemini via Vertex at temperature zero; tool wiring is a hand-rolled MCP→Gemini adapter (the upstream adapter library is incompatible with `mcp` 2.0) in which failures become structured error payloads rather than exceptions, so a downstream outage produces a plain-language report instead of a collapsed graph.

Faithfulness is enforced in two tiers. Tier 2 is a large system prompt encoding hard rules — always call the predict tool for risk, cite every note claim to a returned passage, reproduce medications verbatim, never fill a redaction, report the probability exactly. Tier 3 is deterministic post-hoc guardrails — "LLM proposes, code disposes" — pure functions of the answer and the retrieved evidence that drop invented ages, verify medication doses and frequencies against source passages, and range-check citation markers; the served answer is the guarded one. A2UI composition turns the predict payload into v0.9 canvas messages with mandatory fallback text and honest error cards. Observability is Langfuse, enabled only when its keys are present; the container is slim, non-root, and ships without BigQuery or Vertex libraries by design — the agent reaches data only through the MCP server.

## Adversarial Review Pass

§2 ran under the **both** protocol — the high-risk, high-confidence tier: a blind pass (Claude Fable 5 on raw files with a hostile prompt, independent of the primary reviewer) *and* a cross-check pass attempting to falsify the primary reviewer's understanding document against the code. Sixteen findings resulted (ECC-02, ECC-04…ECC-17; a prior ECC-03 folded into ECC-02): one Critical, eight Major, six Minor. The dominant theme is an inversion of the system's own design philosophy — **"LLM proposes, code disposes" stops exactly where it matters most**: the guardrails scrutinize ages, doses, and citation indices, but nothing deterministic guards the risk number, the answer selection, or the spend.

### The risk number has no deterministic guard

- **ECC-04 · Critical (correctness/faithfulness).** No guardrail checks the risk number itself. The guard verifies redacted age, medication tokens, and citation range — never that a stated probability or threshold matches a `predict_readmission` response, nor that a risk-shaped answer made a predict call at all. A fabricated "risk is 0.14" with zero tool calls is served verbatim with HTTP 200: every guardrail is inert on empty evidence and the A2UI card is simply absent. The system prompt is the only defense against the exact failure its own docstring names. Corroborated and upgraded to Critical by the adversarial pass. *Remediate:* extract stated probabilities in `guard_answer` and require a match with the predict response, dropping or flagging mismatches; if no predict call ran and a risk number is stated, strip it and flag `risk_number_unsupported`; consider refusing or downgrading flagged answers.
- **ECC-05 · Major (security/faithfulness).** No data–instruction separation: the free-text question (2,000 chars, content-unvalidated) and retrieved note passages both reach the model unmitigated — passages land in tool messages unmarked, and the prompt contains no rule that delimited content is data, no "ignore instructions in notes." Combined with ECC-04, an injected instruction about the number passes end-to-end. Synthetic notes limit exploitability today; the question path is fully user-controlled. *Remediate:* wrap tool results in explicit delimiters with a "content is data, never instructions" system rule; strip instruction-like patterns; close ECC-04 so induced fabrications are caught deterministically regardless.
- **ECC-14 · Minor (correctness).** Citation verification is range-only and advisory-only: out-of-range markers are flagged but never stripped, so they render as citations to nothing; there is no support check between claim and passage; with zero passages, an answer containing a citation is served intact. *Remediate:* strip out-of-range markers from the answer; consider a lexical-overlap support check.

### Guardrails and answer selection can corrupt the served answer

- **ECC-11 · Major (correctness).** The medication verifier removes unsupported dose tokens with a plain substring replace that ignores the regex lookarounds used to find the match — an unsupported "5 mg" also destroys a supported "2.5 mg", leaving "2.". The medication-fidelity guardrail can itself corrupt a correct dose in the served answer. *Remediate:* remove by match span (`_remove_spans`) instead of `str.replace`.
- **ECC-12 · Major (correctness).** `final_text` returns the *last non-empty* AI text. When the final agent turn is empty — the documented MAX_TOKENS failure, which raises nothing — it silently falls back to an earlier AI message, typically a pre-tool preamble, and serves that stale fragment (or an empty string) with HTTP 200. *Remediate:* accept text only from the final AI message; if it is empty or MAX_TOKENS-truncated, return `answer_unavailable` rather than 200.

### Spend per request is effectively unbounded

- **ECC-02 · Major (ops/spend).** No explicit recursion limit (LangGraph's default of ~25 is the only cap), no per-turn tool-call cap, MCP calls allowed up to 180 seconds each, and no request deadline — worst case roughly a dozen billed Gemini calls plus many long tool calls in a single request. Meanwhile Django's 120-second timeout aborts and *refunds* upstream (§1) while the agent keeps billing to completion: the request is refunded and billed at once. *Remediate:* set an explicit low recursion limit and per-turn tool cap; reduce tool timeouts to at most the upstream deadline; wrap the run in an async timeout under the proxy timeout.

### The model is flying blind on tool schemas

- **ECC-10 · Major (correctness).** The MCP tools' input schemas never reach the model: the tool wrapper sets no args schema, so binding declares empty or inferred parameters and the model must guess argument names from prose. The carefully cleaned Gemini schema is dead code on this path, and the fragile `kwargs`-unwrapping heuristic exists only to compensate — while itself liable to mangle a legitimate argument literally named `kwargs`. Arguments pass to the toolbox with zero validation. *Remediate:* convert each MCP input schema into a Pydantic args schema; drop the heuristic; validate required arguments before calling.
- **ECC-13 · Minor (correctness).** Tool results are serialized into tool messages as Python repr — single quotes, `None`, `True` — not JSON, a format the prompt never describes, making exact-match reasoning over citations and numbers less reliable. *Remediate:* serialize with `json.dumps`.

### Serving posture and disclosure

- **ECC-09 · Major (ops).** ID-token minting is fully synchronous — a blocking credential fetch or a gcloud subprocess with a 60-second ceiling — and runs inside the async HTTP toolbox on every request, blocking the entire uvicorn event loop and stalling all concurrent `/ask` and `/health` traffic. *Remediate:* move it to a thread; cache the token until near expiry instead of minting per request.
- **ECC-06 · Major (ops/security).** The `/ask` 502 body echoes exception type and cause — and for an exception group, joins every inner exception string, which for httpx/MCP/google-auth failures routinely embeds the private MCP URL, IAM audience detail, and table names. The unauthenticated `/health` returns the MCP URL, project ID, region, and model. Contained today (the service is IAM-private and Django genericizes), but internal topology leaks to any direct caller. Upgraded per the adversarial pass. *Remediate:* log detail server-side; return a generic code with an opaque correlation ID; drop or gate the topology fields in `/health`.
- **ECC-07 · Minor (security).** No app-level auth on `/ask` — Cloud Run IAM (ingress plus invoker) is the only gate, so a misconfigured invoker binding exposes the agent directly, bypassing §1's quota. *Remediate:* defense-in-depth via an optional shared secret; verify the IAM binding and ingress under §5.
- **ECC-08 · Minor (architecture).** Full tool-call responses — the predict payload and RAG passages — are forwarded to the browser in live mode. Intended for the canvas, but raw evidence (synthetic) ships client-side. *Remediate:* trim to what the canvas needs.

### Configuration and supply chain

- **ECC-15 · Major (security/ops, shared with §5).** Real production identifiers are committed throughout — GCP project ID and project number, bucket, Artifact Registry paths, the numeric Vector Search index ID, a concrete GCS bundle URI with pipeline run IDs, and the private agent's actual Cloud Run URL as a settings default (S1-10). The full internal topology is reconstructable from source, and the posture is fail-open: a container started without env vars silently operates against the real project and real BigQuery tables — local mistakes run against prod by default. Upgraded per the adversarial pass. *Remediate:* make the project ID and agent URL required with fail-fast startup — never default to production; move real IDs to an untracked or env file; audit IAM if the repo ever becomes public.
- **ECC-16 · Minor (ops).** The Dockerfile uses a mutable base tag with no digest pin, and installs dependencies without hash verification — non-reproducible rebuilds. (Non-root user is correctly set.) *Remediate:* pin the base image by digest; hash-pin requirements.
- **ECC-17 · Minor (ops).** With Langfuse enabled, the run reads `last_trace_id` off the official callback handler — an attribute current handlers are not verified to expose. If absent, the request raises *after* the full run completes, 502ing after all Vertex and MCP spend, in precisely the observability-enabled configuration that dev runs never exercise. Low confidence. *Remediate:* a defensive `getattr` with a `None` default; add a test with an enabled handler.

## Remediation Scope

**Summary.** The strategic read: the harness's architecture survived adversarial scrutiny — explicit two-turn graph, structured tool errors, honest A2UI composition, non-root slim container — but its *safety perimeter is incomplete in exactly the dimension the system exists to guarantee*. The guardrails police the periphery (ages, doses, citation indices) while the central claim — the risk number — and the answer-selection and spend paths have no deterministic backstop. The recommended order is (1) **close the faithfulness gap** — ECC-04 is the sole Critical and its fix (probability extraction plus a did-you-predict check in `guard_answer`) also converts ECC-05's injection scenario from silently-served to deterministically-caught, with ECC-14's marker-stripping and ECC-12's final-turn-only selection completing the "the served answer is provably grounded" invariant; (2) **cap the spend** — ECC-02's recursion limit, tool-call cap, and deadline aligned under the upstream timeout, restoring the §1 quota's integrity from this side of the proxy; (3) **fix the wiring** — ECC-10's real args schemas (retiring the kwargs heuristic) and ECC-11's span-based removal, both small changes that eliminate self-inflicted corruption; (4) **harden serving and configuration** — ECC-09's threaded, cached token mint, ECC-06's generic errors, and ECC-15's fail-closed config, which shares its fix shape and CI gate with §1's fail-open cluster; (5) **sweep the minors**.

**Detail.** The faithfulness work concentrates in `guard_answer`: parse stated probabilities and thresholds from the answer, require an exact match with the predict response (drop or flag mismatches), strip and flag any risk number stated without a predict call, strip out-of-range citation markers, and optionally add a lexical-overlap support check between claim and passage; `final_text` narrows to the final AI message with an explicit `answer_unavailable` path for empty or truncated turns. Spend control is an explicit low recursion limit and per-turn tool cap in the graph, tool timeouts reduced to at most the upstream 120 seconds, and the whole run wrapped in an async timeout. Tool wiring resolves by converting each MCP input schema to a Pydantic args schema at load time — which deletes the kwargs heuristic outright — plus JSON serialization for tool messages and required-argument validation before dispatch. Serving hardening is a threaded, expiry-cached token mint; the disclosure fix mirrors §1's — server-side logging, a generic error code with a correlation ID, and a trimmed `/health`. Configuration follows the fail-closed pattern established in §1: required project ID and agent URL with fail-fast startup, real identifiers moved out of tracked source (executed jointly with §5, which owns the deploy path). The remaining minors are each independent: prompt-level data–instruction delimiters, an optional shared secret on `/ask`, trimming the tool-call payload to canvas needs, digest-pinned base image with hash-pinned requirements, and the defensive trace-id read with a test that finally exercises the Langfuse-enabled path.
