# §4 — RAG: Index Build, Retrieval, Citation Grounding

## Scope

This section covers the retrieval stack behind the notes evidence: the `rag/` package (deliberately pure stdlib — no cloud calls at import) and the index-build `scripts/`. The serving tool itself was reviewed under §3; §4 asks how the index is built, how passages are chunked and grounded, and how consistency between build and serving is guaranteed — the last question being the one the design stakes everything on.

The foundation is section parsing. Discharge notes are semi-structured, so `parse_note` splits only on an explicit allowlist of roughly twenty-nine canonical headings and their aliases (including MTSamples variants); a heading-shaped line not on the list is counted as unknown and left in the enclosing body, on the stated principle that under-splitting dilutes retrieval while over-splitting truncates it. Chunking turns each section into one or more citable passages — one chunk is one Vector Search datapoint — splitting long sections paragraph-first, then sentence, then a fixed-width fallback, dropping redaction-only pieces (they cost embedding money and can never support a citation), and optionally packing small pieces greedily for line-oriented sections. The chunk id is deterministic (`note_id:section:ordinal`), which makes re-indexing idempotent and — critically — lets serving *re-run the chunker* to reproduce the exact passage a citation points at, rather than returning the whole note. Embedding helpers (gemini-embedding-001 at 768 dims, document/query task types, the `hadm_id` restrict namespace) are shared by build and serving precisely so the two sides cannot drift. The note cache is gzipped JSONL under `~/.cache` with a manifest-verified count; concept tagging (medspaCy + ConText) is precomputed at ingestion and feeds evaluation, never serving. The build pipeline runs `build_chunks.py` → `embed_chunks.py` → `deploy_index.py`, the last implementing a two-index approach: a small BRUTE_FORCE index for exact ground truth at pennies alongside the full TREE_AH serving index, with a datapoint-count assertion so a silent shortfall fails loudly.

## Adversarial Review Pass

§4 ran under the **cross-check protocol**: the adversarial pass read the Understand document and tried to falsify its claims against the code. Fourteen findings resulted (ECC-32…ECC-45), and the dominant theme is that the design's stated invariants — determinism, shared helpers preventing drift, fail-loud verification — are each genuine in intent yet each has at least one path that quietly violates it. The central claim, that build and serving cannot diverge, was falsified outright.

### The critical: serving cannot reproduce the index it queries

- **ECC-32 · Critical (correctness).** The deployed index is built with `pack_to=700`, but serving's `_chunk_texts_for` re-chunks with the default `pack_to=None`. On any packed (long) section the chunk ids differ, the lookup misses, and the code falls back — silently, with no log or flag — to returning the *entire note* as the "cited passage," including non-indexed metadata sections (name, unit number, dates). This is exactly the whole-note leakage the module's own docstring says it prevents, and `count_hybrid_chunks.py`'s own numbers prove the corpora diverge: 307 unpacked chunks versus 136 packed. *Remediate:* thread build-time `pack_to`/`max_chars` through serving config as a single shared constant; log and flag the whole-note fallback so drift is observable.
- **ECC-43 · Minor (correctness).** Downstream of the same mismatch, `rag_search_sections` builds citation ids from the unpacked serving re-chunk, so for long sections the ids name datapoints that don't exist in the index — citations that cannot be traced to any retrieval result. It also cites only the first fragment of a long section and stamps `score: 1.0`, implying a full-confidence retrieval that never happened. *Remediate:* chunk with build parameters; mark these passages as deterministic (non-retrieved) rather than perfect-score.

### The chunker and parser violate their own contracts

- **ECC-41 · Major (correctness).** The second parsing pass treats *any* line consisting solely of a common single-word alias — "History," "Medications," "Condition" — as a section boundary, reintroducing the truncation the module docstring explicitly avoids, and shifting chunk ordinals (hence ids) corpus-wide whenever notes contain such lines. *Remediate:* restrict the bare-heading pass to multi-word or uppercase-only aliases, or a per-alias opt-in list.
- **ECC-34 · Minor (correctness).** The fixed-width fallback for run-on sentences cuts at `max_chars` mid-word, producing chunks that begin and end mid-token — degraded retrieval, and a citation pointing at a fragment that starts mid-word. *Remediate:* split on the last whitespace at or before the limit before hard-cutting.
- **ECC-44 · Minor (correctness).** Redaction-only pieces are filtered before packing, but `_pack` merges spans as first-start-to-last-end — so a filtered piece *between* two kept pieces is re-included in the packed text. Redacted runs still get embedded inside packed chunks. *Remediate:* build packed spans from the kept pieces' boundaries only.
- **ECC-35 · Minor (correctness).** The deterministic redaction guard covers only age. Every other `___` redaction — dates, names, facility, doses — reaches the model via chunks and relies on the prompt alone ("never fill a redaction"), leaving no hard backstop for the risk-critical fields that matter most. *Remediate:* extend the guard to other high-value fields; at minimum, flag answers containing concrete values the source redacted.

### The build pipeline fails silently, then verifies against a fiction

- **ECC-38 · Major (correctness).** In both the script and pipeline embed steps, `zip(batch, resp.embeddings)` silently truncates when the API returns fewer embeddings than inputs — chunks vanish from the ingest with no error, and the per-record dimension check runs after truncation so it cannot catch the loss. The only backstop is the index count assertion, which is itself broken (ECC-40). *Remediate:* `zip(..., strict=True)` or assert the lengths match; fail the batch.
- **ECC-39 · Major (ops).** Inverted exit semantics in `embed_chunks.py`: failed batches print, increment a counter, and continue — the run uploads to GCS and exits as if fine — while `main()` returns a dict, so `SystemExit(main())` exits *nonzero on success*. A run with dropped batches looks clean; a clean run looks failed. Poison for any wrapping automation. (The pipeline component raises correctly.) *Remediate:* return zero only when no batch failed; skip the upload when any did.
- **ECC-40 · Major (ops).** The count verification that everything else leans on asserts against `expected = 555770` — a hardcoded magic number from the original MIMIC corpus, wrong for the current 136-chunk hybrid corpus and any rebuild. The script fails spuriously, or if the number ever coincides, passes wrongly; there is no `--expected` flag and no derivation from the ingest it just read. *Remediate:* count records in the ingest source (already streamed for the brute-force sample) or require `--expected`.
- **ECC-45 · Minor (ops).** Only the notes cache is manifest-verified; `iter_chunks` has no count check, so a truncated `chunks.jsonl.gz` reads as a short-but-valid corpus. And `iter_notes`' own verification fires only on full exhaustion — an early `--limit` break skips it. *Remediate:* add a manifest/count check to `iter_chunks`; verify on open, not on exhaustion.

### Deletion that doesn't delete

- **ECC-42 · Major (ops).** In the prune script, an index-removal failure is caught, printed, and execution *continues* to delete the BigQuery source rows, then exits zero; removal is also submitted asynchronously with no completion check. The result inverts the retirement contract: stale vectors stay queryable while their source text is gone, so later retrieval trips `missing_text`. *Remediate:* abort nonzero before the BigQuery deletes when index removal fails or cannot be confirmed.

### Build-side security posture

- **ECC-36 · Major (security, shared with §5).** The Vector Search index endpoint is created with `public_endpoint_enabled=True` — internet-reachable, gated only by IAM, inconsistent with the private agent/MCP posture. Combined with the §5 finding that a code path can deploy the real MIMIC-derived index, a public endpoint is unnecessary exposure and a DUA/data-governance risk. *Remediate:* use a private endpoint (PSC/VPC), or enforce that only synthetic-note indexes reach the public endpoint — a vector-count guard in the shared deploy path, not just the wrapper.
- **ECC-37 · Major (security).** A CWE-89 surface on the pipeline side: `split_name` and the table refs are runtime pipeline parameters interpolated directly into SQL f-strings, unlike serving, which parameterizes. Exploitability is low — the parameters are operator-controlled at submit — but it is an unnecessary injection surface and a repointing risk. *Remediate:* bind `split_name` as a query parameter; validate table refs against a strict pattern or allowlist.

### One vocabulary, three lists

- **ECC-33 · Minor (maintainability).** The section vocabulary is duplicated in three hand-maintained lists: the build whitelist (13), serving's known-sections list (13), and the parser's canonicals (~29). They can silently diverge — sections dropped at build or unparseable at serving. *Remediate:* derive all three from one source in `rag.sections`; add a consistency test.

## Remediation Scope

**Summary.** The strategic read: the architecture's central bet — deterministic chunking shared between build and serving, so a citation always resolves to the exact indexed passage — is the right bet, but it holds only if the chunker's *parameters* are as shared as its code, and today they are not. The recommended order is (1) **close the determinism breach** — ECC-32, ECC-43, and ECC-33 share one fix shape (a single source of truth for chunker parameters and section vocabulary, consumed by both sides, with the whole-note fallback made loud), and together they restore the property everything else assumes; (2) **make the pipeline's verification real** — ECC-38, ECC-39, ECC-40, and ECC-45 form a chain in which each silent failure's supposed backstop is itself broken, so fixing them as a set converts the build from optimistically silent to fail-loud end to end; (3) **fix the retirement path and the exposure** — ECC-42's ordering bug violates a data-governance contract, and ECC-36/ECC-37 bring the build side up to the parameterized, private posture serving already has; (4) **sweep the chunker minors** — bare-heading over-split, mid-word cuts, packed-span redaction leakage, and the broader redaction backstop.

**Detail.** The determinism breach resolves with one shared constants module: build-time `pack_to`/`max_chars` and the section whitelist defined once (derived from the parser's canonical names), imported by `build_chunks`, the pipeline component, and serving's re-chunker alike, plus a consistency test and a logged, flagged whole-note fallback so any future drift is observable rather than silent — which also converts `rag_search_sections` to citing real datapoints and honest scores. Pipeline integrity is four small changes with one intent: strict zip (or an explicit length assertion) failing the embed batch, exit codes that reflect failure and gate the GCS upload, an expected-count derived from the ingest actually read (or a required flag), and a manifest check on the chunks cache that verifies on open. The prune fix is an ordering change — confirm index removal completed before touching BigQuery, exiting nonzero otherwise. The security pair: move the index endpoint private or enforce a synthetic-only guard in the shared deploy path, and parameterize `split_name` with table-ref validation, matching the discipline serving already demonstrates. The chunker minors are each independent, local changes: an opt-in or stricter pattern for bare headings (ECC-41 — noting it also shifts chunk ids corpus-wide, so it should land before any rebuild), word-boundary-aware fallback cuts, packed spans built from kept pieces only, and a redaction guard extended beyond age — or at minimum instrumentation that flags an answer supplying a value its source redacted.
