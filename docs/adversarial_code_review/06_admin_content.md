# §6 — Admin + Content

## Scope

This section covers `content/` in the danielmherman site repo: the public blog and portfolio (home, articles, projects, resume, contact) plus the Django admin — the second public surface after the demo (§1). Content is authored by staff through the admin using CKEditor 5 rich-HTML fields on `Article` and `Project`, with slugs auto-generated from titles on save; a `ContactMessage` model receives submissions from the one anonymous write path on the site, the public contact form.

The public views are stock Django class-based views with deliberate visibility filters: article routes filter `is_published`, the project list filters `is_active`, and draft previews sit behind `staff_member_required`. Projects flagged for drill-down are split on `<h2>` headings by a custom `HTMLParser`-based sectioning module into landing-page cards and per-section URLs — the one genuinely non-trivial mechanism here, and the only one with tests.

The rendering model is the defining design decision: rich HTML is emitted unescaped by design — `article.content|safe`, `project.content|safe`, and `section.body|safe` — because formatting requires it. The declared trust boundary is *staff-only authoring*, not sanitization: the server performs no HTML cleaning at any point, and the CKEditor configuration (owned here, though it lives in settings as S1-13) allows every element and attribute. The admin itself is conservative — preview links via `format_html`, contact messages read-only and auto-escaped — but sits at Django's default path with no throttling, tracked under §1.

## Adversarial Review Pass

§6 ran under the **cross-check protocol**: the adversarial pass read the primary Understand document and tried to falsify its claims against the code. The protocol earned its keep immediately — it caught the section's most consequential finding, S6-13, by disproving the doc's claim that the project detail views filter `is_active`, and it upgraded two contact-form findings to Major. Thirteen findings resulted (S6-01…S6-13); the dominant theme is a **trust boundary with no backstop**: the site bets everything on staff-only authoring, and every layer that could catch a failure of that bet — server-side sanitization, CSP, SRI, tests — is absent.

### The unescaped-render surface

- **S6-01 · Major (security).** Stored XSS with no server-side sanitization. The cross-check reframed the root cause: CKEditor's `htmlSupport` allow-all is *client-side editor config* — the server never sanitizes, so any HTML written into `content` (via the admin's source-editing mode, a direct DB write, or any client) executes for every visitor through the `|safe` templates. The boundary is staff-only authoring with nothing behind it. *Remediate:* add a server-side sanitizer (bleach/defusedhtml) before render; restrict `htmlSupport`; treat authoring as trusted-but-limited.
- **S6-06 · Major (security/correctness).** The sectioning round-trip *un-escapes* entities and re-emits raw HTML: `handle_data` decodes `&lt;` to `<` under `convert_charrefs=True`, and the renderer re-emits attribute values unescaped. Author-escaped text — `&lt;script&gt;`, code samples containing `<` or `&amp;` — becomes live markup in drill-down section bodies, and a decoded quote in an attribute breaks out of its tag. This is an escalation beyond "staff HTML renders verbatim": it converts content the author deliberately made inert into executable markup. *Remediate:* re-escape in `handle_data`/`_render` with `html.escape`, or keep character references verbatim (`convert_charrefs=False`).
- **S6-11 · Minor (security, latent).** The `first_sentence` template filter declares `is_safe=True` — a wrong promise, since it does not escape. Harmless today because its inputs are unsafe strings and autoescape applies, but it would propagate safeness if ever chained after `|safe`; truncation at the first `.` can also bisect an entity. *Remediate:* drop `is_safe=True`.

### No defense-in-depth for a `|safe` site

- **S6-10 · Minor (ops).** No Content-Security-Policy anywhere — the only realistic backstop for a site that renders `|safe` rich HTML plus CDN scripts (shared concern with §7's demo JS; HSTS absence is S1-12). *Remediate:* `django-csp` with an explicit script-src allow-list; add HSTS.
- **S6-09 · Minor (security, supply chain).** Third-party JS/CSS load from CDNs without SRI — Bootstrap, FontAwesome, Prism, and Mermaid on a floating `@10` — so a CDN compromise or malicious patch is site-wide XSS; Mermaid additionally renders staff-authored diagram text client-side, a historically XSS-prone path. *Remediate:* pin exact versions with `integrity`/`crossorigin`, or self-host via staticfiles.

### Visibility controls that don't hold

- **S6-13 · Major (security/authz).** Inactive projects are publicly served. The Understand doc claimed `ProjectDetailView` and `ProjectSectionView` filter `is_active`; they do not — neither defines a `get_queryset`, so only the list view filters. Deactivating a project removes it from the index while its detail page and every section URL stay public — drafts and retracted content remain reachable, and slugs are guessable. The cross-check caught this by falsifying the doc. *Remediate:* add `get_queryset` returning `Project.objects.filter(is_active=True)` to both views.
- **S6-08 · Minor (security).** A section slugged `preview` is shadowed by the staff preview route, which matches first — a legitimate h2 titled "Preview" links public visitors to a staff-login-gated URL. *Remediate:* move previews to a non-colliding prefix or reserve the slug.

### The contact form: the one anonymous write path

- **S6-02 · Major (ops).** No rate limiting or spam protection (upgraded per cross-check): any anonymous POST creates a `ContactMessage` row, and the message field is an unbounded `TextField` — a bot can insert unlimited multi-MB rows, bloating production Postgres and burying real inquiries. *Remediate:* a Django `Form` with `max_length`, per-IP cache-based throttling, and a honeypot field.
- **S6-03 · Major (correctness).** No server-side validation, and a 500 in production (upgraded per cross-check): `objects.create()` skips validation, so over-length name, email, or subject values raise `DataError` on production PostgreSQL — an unhandled 500 — while dev SQLite silently stores them, hiding the bug locally. The HTML `required`/`type=email` attributes are the only validation and are trivially bypassed. *Remediate:* a `ModelForm` with `is_valid()` fixes length and email validation and the 500 in one move.
- **S6-12 · Minor (correctness).** The error path loses user input — it re-renders the bare template with no context — returns 200 for a failed submission, and accepts whitespace-only values (the all-fields-present check passes for `" "`). *Remediate:* a bound `Form` re-rendered in context, with stripping fields.

### Authoring correctness and coverage

- **S6-07 · Major (correctness).** Drill-down projects silently drop all content before the first `<h2>`: body parts emitted while no section is pending are discarded, so an author's intro paragraphs vanish from the landing page and every section page with no warning — the test fixture itself contains an uncovered `<p>intro</p>`. *Remediate:* emit a synthetic intro section, or render pre-heading content above the card grid.
- **S6-04 · Minor (correctness).** Slug auto-generation via `slugify(title)` means two items with the same title collide on the unique constraint — a 500 on admin save. *Remediate:* dedupe with a suffix, or handle `IntegrityError` with a clear message.
- **S6-05 · Minor (ops).** Only the sectioning module has tests. There are no tests for the public content surface at all: view auth gating on staff previews, publishing/active filters, the contact form, or the `|safe` rendering — which is precisely how S6-13's filter gap survived. *Remediate:* view/rendering tests mirroring the demo's gates.

## Remediation Scope

**Summary.** The strategic read: this section has one architectural bet — staff-only authoring in place of sanitization — and the review found that bet unhedged on every axis: no server sanitizer (S6-01), a sectioning pass that actively *creates* markup from inert text (S6-06), no CSP (S6-10), no SRI (S6-09), and no tests to notice when a visibility filter goes missing (S6-05, S6-13). The recommended order is (1) **fix the two live correctness-of-trust defects** — S6-13's public inactive projects and S6-06's entity un-escaping, both small, surgical changes with immediate effect; (2) **hedge the authoring bet** — S6-01's server-side sanitizer together with S1-13's editor allowlist and upload-permission fix, executed as one unit; (3) **rebuild the contact form properly** — S6-02, S6-03, and S6-12 collapse into a single `ModelForm`-plus-throttle change; (4) **add the backstops and sweep the minors** — CSP, SRI, the pre-h2 intro fix, slug dedupe, the `is_safe` correction, the preview-slug collision, and the test suite that keeps all of it honest.

**Detail.** The trust-defect pair is two localized edits: a `get_queryset` on each project detail view restoring the `is_active` filter, and either `html.escape` in the sectioning renderer or `convert_charrefs=False` so character references pass through verbatim — the latter also simplifies reasoning about round-trip fidelity. Hedging the authoring bet means sanitizing on the server before render with bleach or equivalent (noting S1-16: the pinned bleach itself carries advisories and must be upgraded first), restricting CKEditor's `htmlSupport` to a concrete allowlist, pinning uploads to staff, and revisiting the world-readable storage ACL — the full S1-13 package lands here. The contact form is one coherent change: a `ModelForm` with `max_length` and stripped fields, `is_valid()` gating the write (eliminating the Postgres 500), per-IP throttling plus a honeypot, and the bound form re-rendered with a non-200 on failure. The backstops are `django-csp` with an explicit script-src allow-list and SRI-pinned (or self-hosted) vendor assets — cheap insurance that converts any future missed sink from site-wide XSS into a contained failure. The remaining minors are each independent: a synthetic intro section for pre-h2 content, suffix-deduped slugs, dropping the false `is_safe` promise, and a reserved or re-prefixed preview route. The test additions from S6-05 close the loop — auth gating, publishing filters, form validation, and rendering assertions are exactly the checks that would have caught S6-13 before the adversary did.
