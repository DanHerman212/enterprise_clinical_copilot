# §7 — Front-end JS

## Scope

This section covers the browser half of the demo: the hand-written modules in `static/js/` — `demo_flow.js`, `demo_splitpane.js`, `demo_a2ui.js` — plus the vendored A2UI renderer under `static/vendor/a2ui/`. Two demos share one flow module and differ only in canvas renderer: the custom demo (`/demo/`) paints RISK / DRIVERS / SOURCE / TRACE widgets by hand, while the A2UI demo (`/demo/a2ui/`) feeds the agent-composed envelope into the vendored `MessageProcessor` and mounts a fresh surface per run. The shared flow owns everything stateful: the patient rail (search, pagination, selection), the conversation thread (chapters, starter chips, free text), the ask flow (POST JSON with the CSRF token read from the cookie), episodic per-patient memory, sidebar view switching, and the trace toggle.

The defining property of this code — and the review's central question — is its escaping discipline. Every data path from model output to pixels is defended by one of four mechanisms: `esc()` (which escapes `& < > " '` in the right order), direct `textContent` assignment, lit's auto-escaping `html` tagged templates in the custom A2UI components (RiskBar, FactorBars, SourceCard, TraceCard), and DOMPurify run over the markdown-it 14 output in the vendored markdown provider — so even A2UI data-model values rendered as markdown are sanitized client-side. Agent prose is markdown built from *escaped* text and inserted via `createContextualFragment`; citations become `<sup>` elements through `textContent`. `envelopeForCite` re-points the A2UI SourceCard to the cited passage using section-intent resolution, mirroring the server. The demo JS has no unit tests; server-side tests cover the envelope and page rendering only.

## Adversarial Review Pass

§7 ran under the **cross-check protocol**: the adversarial model read the primary pass's Understand document and tried to falsify it against the code — the fit for a section where risk was moderate and understanding was already high. Seventeen findings resulted (S7-01…S7-17). The headline is a genuine positive: the strong XSS posture *survived* the hostile read — no exploitable script-XSS was found anywhere in the demo JS. What the adversarial pass added instead is four Majors of a different species entirely: the flow's state machine is not concurrency-safe, and its trust in payload shape is absolute. The client was reviewed as a rendering problem and turned out to have a distributed-systems problem.

### The ask flow is not concurrency-safe

- **S7-06 · Major (correctness).** Nothing disables the composer while a request is in flight, and `post()` resolves by overwriting the *last* turn (`episode.turns[episode.turns.length - 1] = turn`). Send a second ask while the first is pending and answer A is attributed to question B, with the first pending "…" turn stranded forever. *Remediate:* disable ask while pending, or replace the pending turn by identity (`indexOf(pending)`) rather than tail position.
- **S7-07 · Major (correctness).** The patient-switch race paints the wrong patient. `post()` captures the episode at send time and unconditionally renders it on completion, so selecting another patient mid-flight renders patient X's thread and canvas under patient Y's header — cross-patient display contamination in an R1 demo. `turnBlock` compounds it by labeling user turns with `state.current.name` at *render* time (old turns acquire the new patient's name), and if Back was clicked the callback throws on a null `state.current`, leaving the spinner stuck. *Remediate:* guard the response handler (`if (state.current?.hadmId !== requestHadmId) return`) and store the asking patient's name on the turn.
- **S7-08 · Major (correctness).** Unguarded payload-shape dereferences leave the spinner stuck: `agentTurnFromResponse` dereferences `predict.response.model_version` and `rag.response.passages` with no guard on `.response` — precisely the failed-tool shape the server defends against — and the call sits *outside* the try/catch, so the exception is unhandled and the pending turn never resolves. `passageRow`'s `passage.section.replace` on a section-less passage is the same class. *Remediate:* optional chaining (`predict?.response?.model_version`, `rag?.response?.passages`, `String(passage.section || '')`), or move turn construction inside the try.
- **S7-16 · Minor (correctness).** The same cross-patient theme in the trace surface: the empty path never resets `msgPre`, so the "Show composed messages" pane leaks the previous patient's full envelope JSON — note-passage text included — after Back or after selecting a patient with no envelope. *Remediate:* `msgPre.textContent = ''` in the empty path.

### The citation pipeline: one demo got the fix, the other didn't

- **S7-09 · Major (correctness).** The known citation mis-numbering failure mode is fixed in the A2UI demo but *not* the custom demo. The A2UI path resolves citations by `intentSections`; the custom demo maps `^[n]` straight to `passages[n-1]` with no intent resolution — so in the acknowledged failure mode, the custom SOURCE card shows the wrong passage (or none) and `highlightPassage(n)` finds no matching row. If the server renumbers for the custom path too, the mapping is broken by construction. *Remediate:* port the intent-section resolution (or the server-side deterministic mapping) to the custom demo.
- **S7-11 · Minor (correctness).** The citation-marker regex accepts a comma list *or* a single range, never both: mixed `^[1, 3-5]` is left as raw text, while a reversed `^[5-3]` matches but expands to an empty list — `wireCitations` then consumes the marker and appends nothing, and the citation silently disappears. *Remediate:* support mixed lists, guard `a <= b`, and keep the original text on unparseable or empty markers.
- **S7-15 · Minor (correctness).** Source lookup resolves by query equality (`episode.sources.findIndex(s => s.query === turn.query)`), so repeated or null-query turns resolve to the *first* match — a footnote click on a later turn surfaces an earlier turn's passages and cited set. *Remediate:* key sources by turn index, not query text.
- **S7-12 · Minor (correctness).** Start-anchor asymmetry in `extractSection` — and the client and server copies agree on being wrong: the start match is `\balias\b\s*:` anywhere in the note while the end bound requires a line start, so generic aliases (`History`, `Condition`, `Diagnoses`, `Medications`, `Activity`) match mid-sentence and truncate or extract the wrong body. *Remediate:* anchor the start match to line starts `(^|\n)\s*`, consistent with the end bound.
- **S7-17 · Minor (correctness).** `envelopeForCite` edge cases: when the envelope lacks a SourceCard, the no-targeted-sections branch silently returns the clone unchanged — a footnote click appears to do nothing; and when `extractSection` fails, `source.text` falls back to the whole-note text while `source.section` still claims the matched section — a header/body mismatch. *Remediate:* synthesize a SourceCard when missing; fall back the section label alongside the text.

### The residual XSS surface

- **S7-01 · Minor (security, latent).** `api.showEmpty(markup)` assigns `div.innerHTML = markup` — an XSS sink that is safe today only because every caller passes a constant string. A future dynamic caller interpolating an answer or passage into the empty state becomes stored/reflected XSS with no warning. *Remediate:* replace with a safe builder (or escape the parameter) and add a guard comment.
- **S7-10 · Minor (security).** Stock DOMPurify allows `<a href>` and `<img src>`, and there is no CSP behind it — so agent-composed markdown, downstream of retrieved note text, can emit `[click](https://attacker)` or an image beacon that renders inside the trusted clinical canvas: phishing and a user-IP signal. *Remediate:* `sanitize(html, { FORBID_TAGS: ['img'], ALLOWED_URI_REGEXP: ... })` or strip anchors and images entirely — the canvas never needs them — plus a CSP with `img-src 'self'`.
- **S7-03 · Minor (ops, shared with S6-10).** No Content-Security-Policy anywhere: the demo rests entirely on escaping plus DOMPurify, and a single missed sink becomes site-wide XSS with nothing to contain it. *Remediate:* a CSP via `django-csp` with a script-src allowlist covering the vendored bundles.

### Display robustness

- **S7-04 · Minor (robustness).** The client trusts predict payload numbers: a non-numeric `probability` or `threshold` renders `NaN%`/`Infinity%` and the wrong band in `riskBlock`, `driversBlock`, and `pct`. The server composes these, so risk is low, but there is no guard. *Remediate:* validate numbers before render; fall back to the empty state on malformed payloads.
- **S7-14 · Minor (correctness).** Unscored patients render "NaN%" in the thread header today: the template's `data-probability="{{ row.probability }}"` has no `|default` (the band does), so a `None` probability arrives as the truthy literal `"None"` and `pct("None")` yields `NaN%`. *Remediate:* `{{ row.probability|default:'' }}` or a `Number.isFinite` guard client-side.
- **S7-05 · Minor (correctness).** `renderAgentMarkdown` runs its regexes on already-escaped text, so entity and code spans display literally — an answer containing `&amp;` renders as `&amp;` inside a `<code>` span. A display-fidelity quirk, not security. *Remediate:* decode entities in code spans after escaping, or document the behavior.

### Two demos, drifting apart

- **S7-02 · Minor (maintainability).** Client-side `SECTION_ALIASES` is the *fourth* hand-maintained copy of the section vocabulary, after the build whitelist, the serving layer's known-sections list, and the parser canonicals (ties ECC-33). Divergence means citation clicks show the wrong section or extraction fails silently. *Remediate:* generate from one source — or a shared JSON the server emits — with a consistency check.
- **S7-13 · Minor (ops).** Cache-bust version skew: `demo_a2ui.js` imports the shared module as `demo_flow.js?v=16` while `demo_splitpane.js` imports `?v=11`, so the custom demo runs a `demo_flow` five revisions behind the A2UI demo. Manifest-hashed collectstatic doesn't rewrite intra-module import specifiers, making the `?v=` string the only invalidation. *Remediate:* a single source of truth for the version (import map or hashed module filenames).

## Remediation Scope

**Summary.** The strategic read: the security architecture is sound — the layered escaping discipline held under hostile review, and no data path from model output to DOM was found exploitable — but the *state machine* was built for a single patient asking one question at a time, and every Major is a consequence of that assumption breaking. The recommended order is (1) **make the ask flow race-safe** — S7-06, S7-07, S7-08, and S7-16 are one coherent fix (identity-keyed turn replacement, a request-generation guard on the response handler, defensive payload access, empty-path resets) that eliminates both cross-patient contamination and the stuck-spinner failure family in a demo whose entire purpose is credibility; (2) **converge the citation pipelines** — port intent-section resolution to the custom demo (S7-09) and sweep the mapping minors (S7-11, S7-12, S7-15, S7-17) in the same pass, since they all live in the marker-to-passage path; (3) **close the latent injection channels** — tighten DOMPurify, retire the `showEmpty` innerHTML sink, and land the CSP backstop; (4) **sweep the drift and display minors**.

**Detail.** The race fixes are small and local to `demo_flow.js`: capture the asking patient's admission id and name at send time, bail in the response handler when the current patient has changed, replace the pending turn by reference rather than tail index, disable the composer while a request is in flight, wrap turn construction in the existing try/catch with optional chaining on `predict?.response` / `rag?.response` / `passage.section`, and clear `msgPre` on the empty path. Citation convergence means the custom demo adopts the same section-intent resolution the A2UI demo and server already use, sources become keyed by turn index, the marker regex learns mixed lists and rejects reversed ranges without consuming the marker, `extractSection`'s start anchor becomes line-anchored on both client and server copies, and `envelopeForCite` synthesizes a SourceCard when absent and downgrades the section label together with the text on extraction failure. The injection-channel work is a DOMPurify config forbidding images and constraining link URIs, a safe builder for `showEmpty`, and the `django-csp` policy shared with §6. The remaining minors are each one-line to one-function: `Number.isFinite` guards with an empty-state fallback, `|default:''` in the two console templates, an entity-decode pass (or a documented quirk) for code spans, a generated section vocabulary shared with the server, and a single versioning source for the module imports. None of it requires new architecture; all of it is testable, and the section's lack of any JS unit tests argues for landing the race and citation fixes with a small test harness rather than as bare patches.
