# §8 — MLOps: Training, HPO, Serving, Feature Store

## Scope

This section covers the model side of the system: the training pipeline and its components in `projects/mlops/pipelines/`, the custom prediction routine (CPR) that serves the readmission model, the RAG ingest pipeline in `projects/agent-harness/pipelines/`, and the eval suite that anchors the project's rigor claims. The feature store is BigQuery itself — Vertex AI Feature Store was removed for cost, and all encoding is static in the analytics dataset: one-hot plus an explicit missingness policy, so the model consumes a fixed-order numeric vector with no categorical handling at serve time.

The training DAG is deliberately gate-heavy: `load_data → validate_data → benchmark_xgboost → benchmark_gate → optuna_hpo → train_final → calibrate_threshold → evaluate_test / shap_explain / fairness_audit → register_model`. Evidently drift and data-quality checks hard-fail the pipeline when the drifted-column share exceeds a threshold; a benchmark XGBoost must beat the hospital baseline AUCPR before HPO spend is committed; the honest pre-test estimate is the HPO validation AUCPR rather than the final model's combined fit; a fairness audit runs on the test split; an F-beta-optimal operating threshold is calibrated from out-of-fold train predictions; and registration publishes a versioned serving bundle — `model.bst`, `manifest.json`, `threshold.json` — to GCS with a Vertex Model Registry provenance entry. HPO is Optuna (50 trials, bounded wall clock) logged to Vertex Experiments.

Serving is a CPR (`ReadmissionPredictor`): it downloads the bundle, loads the booster in xgboost's native format (not pickle — deliberately lower deserialization risk), accepts positional lists or named dicts with JSON null mapped to NaN as native missing, and returns a calibrated probability, a threshold decision, and native-TreeSHAP attributions aggregated to parent feature groups. The endpoint is IAM-private; the MCP `predict_readmission` tool is the gate. The RAG ingest pipeline (chunk → embed → build-index with verified counts) shares the KFP infrastructure; the eval suite — golden evals plus LLM-judged scoring through Langfuse — is the measurement layer, not the serving path.

## Adversarial Review Pass

§8 ran under the **cross-check protocol**: the adversarial model read the primary pass's Understand document and tried to falsify it against the code. It succeeded twice, and the failures are the story of this section. The Understand doc's closing judgment — "the gates are strong — a well-built pipeline" — was falsified outright (the baseline the gates compare against is submitter-controlled), and the cross-check surfaced the section's only Critical: nothing in the pipeline ever asserts that train, validation, and test are patient-disjoint. The merged result is fourteen findings, ECC-60 through ECC-73 (ECC-62 folded into ECC-61): one Critical, five Major, seven Minor, plus the CWE-scan finding ECC-31 owned here. The dominant theme is that the pipeline's *architecture* of gates is sound while the *evidence* those gates consume is unverified — splits trusted blindly, baselines passed as parameters, references statistically biased, artifacts fetched without checksums.

### The eval gates measure contaminated or bypassable evidence

- **ECC-64 · Critical (correctness/leakage).** No train/val/test patient-disjointness assertion, in `load_data` and therefore the whole pipeline. The loader blindly trusts the upstream `split_name` column; all the grouped-CV machinery protects disjointness only *within* train/val. If any patient's admissions straddle train and test, the test AUCPR gate, the stability check, and the fairness audit are all contaminated — every downstream guarantee rests on a property never checked. The `id_col` is already loaded for every split; the assertion is one line of set arithmetic away. *Remediate:* assert disjoint train/val/test id sets in `run_load_data` and hard-fail on overlap.
- **ECC-65 · Major (correctness/gate integrity).** The performance gates are bypassable: `hospital_aucpr` is a runtime pipeline parameter, so any submitter can pass `0.0` and neutralize both `benchmark_gate` and the eval hard-fail. The build-time source is an unversioned local JSON, and there is no minimum margin or confidence interval — a 0.0001 improvement passes. *Remediate:* resolve the baseline inside the gate from a versioned, access-controlled artifact, record its provenance, and require a margin.
- **ECC-66 · Major (correctness/gate effectiveness).** The val→test stability check is warn-only — a badly overfit model still registers. Its reference, `hpo_val_aucpr`, is `study.best_value`: the maximum over ~50 trials (winner's curse, optimistically biased) computed on a 50% subsample with 3-fold CV — a different regime from the full-data final model, which makes the fixed 0.02 threshold statistically arbitrary. *Remediate:* make stability a hard gate with a defensible reference (a clean refit-CV estimate), or drop the "honest generalization" framing.
- **ECC-67 · Minor (correctness).** The operating threshold is selected from out-of-fold probabilities of CV models trained on train-only, then applied to a *different* model refit on train plus 80% of val with full `n_estimators`. The refit model's probability distribution shifts, so the served `threshold.json` sits systematically off its F-beta optimum. *Remediate:* recompute or verify the threshold on the final model's val predictions; report the F-beta the final model actually achieves at the shipped threshold.

### The serving contract is undeclared

- **ECC-60 · Major (security).** Zero input validation on the CPR endpoint (upgraded per cross-check). A dict instance with a typo'd or missing key silently becomes NaN, which XGBoost treats as "missing" — returning a confident, silently wrong probability, the worst possible failure for a clinical score. Positional lists of the wrong length surface as raw shape errors or opaque 500s; `float(v)` accepts `inf`, `nan`, and booleans and raises an unhandled `ValueError` on other garbage; there is no batch cap. *Remediate:* validate per instance — dict keys a subset of `feature_order` with unknown-key rejection, list length equal to `feature_order`, non-finite values rejected — return 400-style structured errors, and cap batch size.
- **ECC-68 · Minor (correctness).** If `threshold.json` is absent (it is only written when a tuned threshold exists), the CPR silently falls back to 0.5. For a recall-weighted F2 threshold — typically well below 0.5 — that silently flips many readmit decisions to negative with no error or log. *Remediate:* fail `load()` loudly when the file is missing, or emit `"threshold_source": "default"` in every response.
- **ECC-73 · Minor (correctness).** `pred_contribs=True` on a `binary:logistic` booster returns TreeSHAP contributions in log-odds (margin) space, but the response pairs them with a probability, and a stale comment in `train_final.py` claims "probability units." The response never declares units, so a consumer could misread attributions as probability deltas. *Remediate:* declare attribution units in the response and manifest; fix the stale comment.

### The supply chain is mutable end to end

- **ECC-61 · Major (security/ops).** End-to-end mutable supply chain (merged ECC-62; upgraded per cross-check): the CPR fetches the serving bundle with no checksum — the bundle writes no hash manifest — provenance points at `:latest`, the CPR cloudbuild's `_TAG` defaults to `latest` so a substitution-less build silently defeats the content-hash-tag design, and the base is unpinned (`python:3.10` plus a `>=` prediction dependency). *Remediate:* write SHA-256 digests into the bundle and verify them in `load()`; record the image by digest; make `_TAG` required with no default; pin the base image.
- **ECC-31 · Minor (security).** From the CWE-502 scan: the training and eval components (`shap_explain`, `evaluate_test`, `fairness_audit`) load model artifacts via `joblib.load` — pickle — with no integrity verification, meaning arbitrary code execution on load if the artifact store or CI output can be tampered with. Deployed serving uses the native `model.bst` format and carries lower risk; the components are the exposure. *Remediate:* verify artifact integrity (hash or signature) before `joblib.load`; prefer native formats; treat the artifact store as trusted-and-verified.
- **ECC-69 · Minor (ops).** Components install unpinned `xgboost`/`optuna`/`scikit-learn`/`pandas` on a `:latest` base (only Evidently is pinned), so runs are not reproducible over time — and xgboost version parity with the CPR, which *is* pinned, is unenforced. *Remediate:* make the pinned custom image the default, pin versions, and record package versions in the registry entry and manifest.
- **ECC-72 · Minor (ops).** The GCP project ID is hardcoded in three more source files (image URIs and env fallbacks) while the training pipeline correctly resolves it from `src.config` — configuration split across sources. *Remediate:* route all project and image references through `src.config` or required env with no baked defaults.

### Pipeline hygiene

- **ECC-63 · Major (security).** All SQL inputs in `load_data` are interpolated (upgraded per cross-check): the table reference, id column, feature columns, label and split columns, and the split-name string literals are all f-string'd into BigQuery SQL with no query parameters. The parameters are operator-controlled and the pipeline runs as the pipeline service account, but a crafted `train_split` can exfiltrate any table that account reads into training artifacts. *Remediate:* pass split names via `query_parameters` and validate identifiers and table refs against a strict regex; the feature columns already come from `encoding.feature_order()` — keep that and document it.
- **ECC-70 · Minor (correctness).** The RAG ingest pipeline runs with `enable_caching=True` while its first step reads BigQuery. The KFP cache key covers code and parameters, not table contents — if the source tables change, a re-submission silently reuses stale chunks and embeddings and builds an index that no longer matches the data. (The training pipeline correctly disables caching.) *Remediate:* add a data-fingerprint parameter — table last-modified or a row-count hash — to the chunking step so the cache key invalidates on data change.
- **ECC-71 · Minor (architecture).** `shap_explain` and `fairness_audit` are not upstream of `register_model` — a crash in either leaves an already-registered model with no audit marker. `Model.upload` is also called with no `parent_model`, so there is no version lineage, and the gate metrics are only printed, never persisted on the registry entry. *Remediate:* gate registration on the fairness (and SHAP) steps or record audit status and URIs; use `parent_model` for lineage; persist gate metrics as model labels or metadata.

## Remediation Scope

**Summary.** The strategic read: the pipeline's gate architecture survived review; the *provenance of everything the gates consume* did not. Every serious finding is a missing assertion about evidence the pipeline already has in hand — the id column is loaded but disjointness never checked, the baseline exists but arrives as a parameter, the bundle is versioned but never checksummed. The recommended order is (1) **restore eval integrity** — ECC-64 first, since a one-line disjointness assertion decides whether every reported metric means anything, then ECC-65's in-gate baseline resolution and ECC-66's hard stability gate, so the gates measure what they claim on evidence a submitter cannot dilute; (2) **harden the serving contract** — ECC-60's per-instance validation plus the ECC-68 threshold guard and ECC-73 unit declaration, because a clinical score that is confidently wrong on a typo is worse than one that errors; (3) **close the supply chain** — ECC-61's digests-and-required-tags, ECC-31's verify-before-unpickle, ECC-69's pins; (4) **sweep the hygiene minors** — parameterized SQL, cache fingerprinting, registration ordering and lineage, config unification.

**Detail.** Eval integrity is cheap in code and decisive in consequence: a set-disjointness assertion over the already-loaded id columns in `run_load_data` (hard-fail on overlap) retires ECC-64; ECC-65 resolves by reading the hospital baseline inside `benchmark_gate` from a versioned, access-controlled artifact with provenance recorded and a required margin, removing the runtime parameter entirely; ECC-66 becomes a hard gate once the reference is a clean refit-CV estimate rather than the winner's-curse `study.best_value`; ECC-67 is a recompute-and-report of the threshold against the final model's val predictions. The serving contract fixes live in one file: `preprocess` gains key/length/finiteness validation with structured 400s and a batch cap, `load()` fails loudly on a missing `threshold.json` (or every response declares its threshold source), and `postprocess` declares attribution units — with the stale training comment corrected alongside. Supply-chain closure is SHA-256 digests written at registration and verified at load, images recorded by digest, `_TAG` made a required substitution, base images pinned, joblib loads preceded by hash verification in the three eval components, and the pinned custom image made the component default with versions persisted to the manifest. The remaining minors are small independent changes: query parameters plus identifier regexes in `load_data`, a data-fingerprint input on the RAG chunking step, `.after(fairness)` ordering plus `parent_model` and persisted gate metrics at registration, and routing the three hardcoded project references through `src.config`.
