threshold, but one item failed structurally, and the criterion `structural_failures == 0`

scenarios (`t3_01`, `t4_01`, `t4_02`) share a single root cause with the structural
failure, and that root cause is a capacity limit, not a reasoning defect.

### 6.2 `holdout_t2_01` — **fixed** (unscored → pass)

The scenario that had no subject on `00d1` now runs to completion on both turns

## 7. The one root cause behind three items and the structural failure

Three observations, one cause.

| item | trace | `/meds` answer |
|---|---|---|
| `holdout_t3_01` T1 | `d24bb020` | retrieved, no medication could be read |
| `holdout_t4_01` T2 | `f712ec16` | retrieved, no medication could be read |
| `holdout_t6_02` T1 | `9981dc35` | retrieved, no medication could be read |
| `holdout_t4_02` T2 | `d20eb25f` | *no specific discharge medication information is available* (different branch — the tool returned zero passages for this record) |

All three refusal traces are admission `90000067`, all three are the same command, and the
same command on the same record succeeded on the previous revision:

```
agent-00211-44h  8a1526c9  "16 discharge medications, as recorded in the discharge note:
                            Home oxygen, Ativan, Metformin, …, Prednisone, Clindamycin ^[1]."
agent-00212-bmh  9981dc35  "The discharge medications section was retrieved, but no
                            medication could be read from it ^[1]."
```

### 7.1 The mechanism

The `/meds` command is a model turn that returns a JSON array of extracted rows, verified
row by row against the passage text. The reply trace for `9981dc35` is 1729 characters and
ends mid-string:

```
… "medication": "Prednisone", "dosage": "40 mg p.o. q.a.m. x3 days followed by 30 mg
p.o. q.a.m. x3 days, then followed by 20 mg p.o. q.a.m. x5 days, then 10 mg p.o. q.a.m.
x14 days, then discontinue
```

No closing quote, no closing braces, no sixteenth row. The reply was cut by
`GEMINI_MAX_OUTPUT_TOKENS = 2048` in `services/mcp/config.py`, an allowance that covers
thinking *and* the answer. `_extract_json_object` refuses the truncated object, `verified`
is empty, `returned_passages` is 3, and `medication_narrative` takes its third branch —
"retrieved, but no medication could be read from it". The sentence is accurate about what
the module saw; the module saw a truncated reply.

### 7.2 Verified offline, not inferred

The extraction reply and the transaction's passage text were both replayed through
`parse_medications`:

| run | reply length | rows returned | rows verified | reason |
|---|---|---|---|---|
| `00d1` (`agent-00211`) | 1836 | 16 | **16** | — |
| `00d2` (`agent-00212`) | 1729 (truncated) | 15 | **0** | `extraction reply was not valid JSON` |

The passage text is byte-identical between the two transactions; the only change in the
input is that `id` is no longer projected to the model (`MT-2616-DS_discharge_medications_2`
and its siblings). The reply that the model produced from that input was a few tokens
longer per row — it copied long verbatim strings into `dosage` and `frequency` — and the
allowance ran out.

### 7.3 What this is, and what it is not

It is not a retrieval defect: the passages are correct and identical across builds. It is
not a verification defect: the verifier refused an unparseable reply, which is its job. It
is a **capacity defect that has been latent since the extraction was written**, on a record
whose medication list is long enough to sit near the ceiling. `00d1` cleared it by roughly
a hundred characters; `00d2` did not. Any change to the passage projection, the prompt, or
the model revision can move that margin.

It is a single cause with four consequences: the structural failure on `holdout_t6_02`
(its `must_contain` fact, `Aspirin`, is in the list that was never extracted); the context 0
on `holdout_t3_01` and `holdout_t4_01` (each thread's next turn reads the section the
previous turn said was unreadable); and the grounding deduction that follows from a refusal
sentence on a turn whose card renders the medications anyway.

### 7.4 `holdout_t4_02` is a different failure

`90000101` returned zero passages for `discharge_medications` (`d20eb25f`), so the
"no specific discharge medication information is available" sentence is the correct branch.
Turn 3 (`75776b5b`) then restated it as *"the discharge medications section is empty
`^[0]`"*. Two defects in one clause, both in the model's prose rather than in the command:
the section was not empty, it was not retrieved, and `^[0]` is not a marker — numbering is
1-based, so the character sequence was invented and no guard removed it. That is the
citation 0.

## 8. What the repairs did do

- **T1 is clean for the first time.** All three declarative-command items pass, including
  the non-monotonic series that failed twice.
- **T2 is clean and measurable.** The chip pool falls back through present factors to record
  anchors, and no chip is offered for a factor the record says is absent.
- **T3 is clean.** The drill-down reaches the panel on pronoun-plus-concern phrasing, which
  is what `00d1` lost.
- **Citation is materially better**: `t3_01` 0 → 3, `t5_02` 0 → 3, `t4_01` 0 → 3,
  `t2_02` 2 → 1 (worse), `t5_01` 2 → 1 (worse), `t4_02` 0 → 0.
- **Non-monotonic trajectories are told as trajectories.** "Remained at / stayed at / held
  steady at" is barred unless every intermediate measurement matches, and the two items it
  cost are now 3 and 3 on fidelity.
- **Safety and unscored are both zero**, and no judge retry was needed.

## 10. Verdict

**Gate 3: FAIL on the documented criteria** — `structural_failures` is 1, against a
required 0. The harness's own gate rule, which omits that criterion, returned
`gate_pass: True` with a pass rate of 0.9333.

The single cause worth fixing is the extraction allowance, not a reasoning path. One
retrieval-succeeded-but-extraction-failed condition produced the structural failure and both
of the context failures, and it will recur on any record whose medication list is long
enough to sit at the cap. Two smaller defects are independent of it: an out-of-range `^[0]`
marker that no guard removes, and a citation dimension that still scores 1 or 2 where two
passages both plausibly carry the claim.

No remediation is proposed here. The fix is a directive question — the allowance is shared
with the thinking budget, so raising it moves cost and latency on every turn, and the
narrower change is a bounded retry or a streaming-safe parse for the extraction turn
specifically.
